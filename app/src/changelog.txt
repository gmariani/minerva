5.0.0 - 2026-11-01
####################################################
    - Replaced Gulp build with Vite
    - Rebuilt the interface with React and TypeScript, replacing jQuery, jQuery UI and jsTree (which had known vulnerabilities)
    - Large files open much faster: the sidebar only draws the rows on screen
    - Select several Numbers, Booleans, Strings, XML or Dates (Shift/Ctrl-click) to set them all to the same value at once
    - JSON exports now include each value's data type (superjson format), so importing them restores Integers, Dates, ByteArrays, classes, shared objects and the AMF version. Turn this off in About > Settings for plain JSON
    - Added a console API for scripting: open the browser console and run minerva.help()
    - Fixed JSON import treating any object with a "value" property as that value
    - Fixed AMF0 object references pointing at the wrong object. Flash Player numbers them differently for ActionScript 2 and ActionScript 3 (neither exactly as the AMF0 spec says); .minerva now works out which a file uses and saves it the same way
    - Fixed files with an unreadable externalized class failing to open instead of showing a warning
    - ByteArrays can now be compressed with LZMA (updated LZMA-JS to 2.3.2)
    - Fixed emoji and other characters above U+FFFF being read wrong and saved as invalid UTF-8
    - Fixed AS2 (AMF0) long strings and XML with non-ASCII text being saved with the wrong length, corrupting the file
    - XML is now saved exactly as written; it was having its leading/trailing whitespace (and, for XMLDocument, whitespace between tags) removed
    - New items in a Vector.<*> are no longer created as objects of class "*"
    - Number keys for new Dictionary entries are saved as strings, as Flash does
    - .minerva is now available under the ISC, MIT or Apache 2.0 license
    - Fixed error thrown when writing an invalid UTF-8 character
    - Fixed workers not being cleaned up after opening/saving files
    - Removed defunct Universal Analytics tracking
    - Fixed object references (shared objects) being read as empty values, which broke many files
    - Objects a file uses in several places can be edited independently; unedited copies are saved as references again
    - Fixed saving after deleting or renaming a member declared by an object's class (these can no longer be removed)
    - Fixed saving large files: files over 5 MB failed, and files with many objects were very slow
    - Fixed saving Flex ArrayCollection, ObjectProxy and SerializationProxy objects
    - Fixed saving arrays that have both indexed and named entries
    - Fixed dynamic members of typed objects being dropped on save
    - Fixed saving changing NaN values, AMF0 date timezones, sparse AMF0 array lengths and Dictionary weak keys
    - Fixed Boolean true values created in the editor being saved as false
    - Truncated files now show a clear error, and keep whatever could be read
    - Fixed text from a file being able to run script in the details pane
    - Fixed search only matching lowercase text
    - Fixed JSON export of arrays and dictionaries ignoring edits; arrays now export as JSON arrays
    - Fixed names containing < or > being saved as &lt; and &gt;
    - Fixed saving a ByteArray after compressing it
    - Fixed dates being shown with the wrong time zone offset
    - Fixed the ByteArray offset column labelling rows one byte early
    - Fixed sidebar sort ordering numbers as text (item10 before item2)
    - Fixed dropdown arrows not showing
